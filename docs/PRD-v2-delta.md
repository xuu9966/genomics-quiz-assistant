## 0. 变更性质与用户原话

这是一次**认知纠正型需求变更**，不是全新项目。

- v1 误把"796 个小 `.md` 文件"当作 796 个独立自测任务（逐文件刷）。
- 用户实测纠正："**同一大章下点进任意小文件，题目是同步的；自测计数以大章节点 id 为键维护；不需要点开每个小章节挨个刷，只需要设置该大章节刷多少次就行。**"
- 核验 §7 已用只读实测证实该认知，推翻 v1.1 §4.1 与核验 §4、提示 2/4 的"796 任务"假设。

**用户已拍板、不可推翻的两项决策：**

| 决策 | 结论 |
| ---- | ---- |
| 自测单元 | **顶层大章节点**（取 `graphData.tree` 的顶层节点，如 `2_测序`、`3_组装`、`4_注释`；不是子文件夹节点） |
| 重复次数 | **默认值 + 可按章覆盖**：全局默认刷 N 次，个别大章可单独设次数覆盖 |

## 2. 新任务模型

### 2.1 定义

```
执行单元 = (顶层大章节点 C, 第 k 次)   k = 1 .. M(C)
M(C) = repeat_overrides[C.name] 若存在，否则 repeat_default
任务计划总量 = Σ M(C)  （对纳入的全部大章求和）
```

- **大章 C**：`graphData.tree` 的顶层节点（可配置白名单），每个有唯一节点 id（如 `2_测序` → `20260907180845_0005`）与名称。
- **第 k 次**：同一大章的每次组卷是一个独立执行单元，有独立状态与唯一键；但共享同一个 `node_id` 与 `kpId`。
- **原"796 文件任务"整体作废**：文件不再是任务单元，仅作为 `md_path` 的取值来源。

### 2.2 示例

| 场景 | 配置 | 生成的执行单元 | 唯一键 |
| ---- | ---- | -------------- | ------ |
| 大章默认 | `repeat_default=3`，只选 `2_测序` | `2_测序::1`、`2_测序::2`、`2_测序::3`（共 3 个） | `20260907180845_0005::1/::2/::3` |
| 按章覆盖 | `repeat_default=3`，`repeat_overrides={"2_测序":5,"4_注释":2}`，选 `2_测序`+`3_组装`+`4_注释` | 2_测序×5、3_组装×3、4_注释×2（共 10 个） | 各章节点 id `::1..M` |
| 任务量对比 | v1：796 文件 = 796 任务；v2：约 9~38 大章 × 默认 3 次 ≈ 27~114 执行单元 | 量级下降一个数量级 | — |

### 2.3 关键不变量（来自核验 §7.2，架构与 QA 必须遵守）

1. 同一大章下，`node_id` 传大章顶层节点 id 时，任意小文件的 `kpId` 与 `selftestInfo` 相同 → 用同一 `node_id` 循环刷即可。
2. 计数键 = 传入的 `node_id` → 传小文件自己的 id 会得到各自独立的 current（错误做法，禁止）。
3. 不同大章的 current 相互独立（实测 `2_测序=8 / 3_组装=11 / 4_注释=6 / 5_数据库=0 / 1_绪论=5`）→ 各章计数互不干扰。
4. 以**本地持久化执行记录**为准判断是否完成，不依赖站点 `selftestInfo.current`（沿用附录 A.11）。

## 3. 变更后的需求条目

### FR-1 账户与配置 —【新增参数】

沿用 v1.1 FR-1.1 / FR-1.2 全部内容，新增以下参数与校验：

| 编号 | 变更 | 内容 |
| ---- | ---- | ---- |
| FR-1.3 | 【新增】 | 新增两个参数：`repeat_default`（全局默认重复次数，**默认 3**，正整数）；`repeat_overrides`（按章覆盖，形如 `{"2_测序":5,"4_注释":2}`，键为大章名称，值为该章重复次数，正整数）。覆盖规则：章名命中 override 用覆盖值，否则用 `repeat_default`。 |

## 4. 验收标准变更

### 4.1 作废 / 改写（供 QA 更新用例）

| 原验收点 | 处理 | 新口径 |
| -------- | ---- | ------ |
| FR-2.1「递归遍历整棵树，796 文件不漏；唯一键=节点id+路径」 | **作废重写** | 只识别顶层大章节点；不按文件拆分；唯一键=`大章节点id::第k次` |
| FR-2.2「限量按文件顺序生效」 | **改写** | `limit` 按大章数生效；任务总量 = Σ M(C) |
| M2「完成率 ≥95%，分母=限量后任务集（文件）」 | **改写分母** | 分母 = 纳入的大章 × 每章次数 = 执行单元总数；排除平台不可用 |
| M5「断点续跑重复生成率 0%（节点id+文件路径）」 | **改写唯一键后保持目标** | 中断续跑，已完成的"大章+次数"组卷接口调用次数为 0 |
| 总览/记录页 UI「文件」列（v1.1 §5.2/5.3） | **作废** | 改为"大章 / 第 k 次"与"每章进度 k/M" |

### 4.2 新增验收点

- [ ] **每章刷 M 次**：`repeat_default=3`、选中单个大章 → 发起 3 次组卷；3 次请求 `node_id` 均为该章顶层节点 id，`md_path` 为该章代表文件。
- [ ] **按章覆盖生效**：`repeat_default=3` + `repeat_overrides={"2_测序":5,"4_注释":2}` → 2_测序 生成 5 个执行单元、3_组装 3 个、4_注释 2 个，计划总量与展示一致。
- [ ] **唯一键新格式**：持久化记录键为 `大章节点id::第k次`（如 `20260907180845_0005::3`），非旧的 `节点id::文件路径`。
- [ ] **同章计数同步**：同一大章不同 k 使用相同 `node_id`/`kpId`（对应核验 §7.2a）；不使用小文件自己的节点 id（对应 §7.2b）。
- [ ] **跨章计数独立**：不同大章各自维护计数，互不串扰（对应核验 §7.2c）。
- [ ] **中途续跑补齐**：某章 5 次完成 2 次后中断，续跑仅补第 3~5 次，已完成的 2 次不重复组卷。
- [ ] **大章清单展示**：启动前面板/终端展示大章名、节点 id、M、次数来源（默认/覆盖）。

### 4.3 未变的成功指标

M1（首次配置 ≤2 分钟）、M3（单套发起→出分 ≤3 分钟）、M4（成绩视图延迟 ≤10 秒）、M6（题库题数 >0 且按题干去重）目标不变。
