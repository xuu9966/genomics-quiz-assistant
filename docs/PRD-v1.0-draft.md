## 1. 产品概述

### 1.1 一句话定义

一款帮助学生在课程平台上**批量完成章节自测、集中查看成绩、并把散落题目整理成可离线复习题库**的本地工具。

### 1.2 问题陈述

课程平台为每一章提供 AI 辅助自测。学生需要重复执行一系列机械操作：进入章节 → 打开资料页 → 发起组卷 → 等待生成 → 逐题作答 → 交卷 → 等待评阅 → 记录分数。章节数量多、文件数量多时，整个过程耗时且容易遗漏。

同时，平台把题目、答案和解析分散在不同类型的历史任务中，学生没有一个统一的地方回看这些内容，期末复习时只能逐条翻找。

### 1.3 产品价值

- 把重复操作压缩为一次配置、一次启动。
- 把"做过但不知道对错分布"变成可量化的成绩视图。
- 把"散落在各处的题"变成一份可搜索、可导出的复习资料。
- 让中断、失败、限流等意外情况可恢复、可诊断。

### 1.4 产品目标

1. 学生能在一次配置后，自动完成选定范围内的全部章节自测。
2. 学生能随时看到整体进度、各章完成度、每套题的得分与异常原因。
3. 学生能把平台中的题目、答案、解析汇总为本地复习题库。
4. 学生在使用过程中不需要把账号密码暴露给代码仓库、日志或网页。

### 1.5 非目标

- 不用于正式考试、闭卷测评或任何监控场景。
- 不修改、伪造或绕过平台成绩与学习记录。
- 不提供云端托管或多人协作服务（首版）。
- 不承诺替代学生对课程内容的理解；题库是复习材料，不是答案替身。
- 不负责平台自身的改版维护；产品通过适配层隔离外部变化。

### 1.6 成功指标

| 指标         | 目标             |
| ---------- | -------------- |
| 首次配置耗时     | ≤ 2 分钟         |
| 选定范围内任务完成率 | ≥ 95%（排除平台不可用） |
| 单套自测从发起到出分 | ≤ 3 分钟（不含平台排队） |
| 成绩视图更新延迟   | ≤ 10 秒         |
| 断点续跑后重复生成率 | 0%             |
| 题库导出可搜索题数  | > 0，且按题干去重     |

## 2. 目标用户与场景

### 2.1 用户画像

| 角色         | 特征                         | 期望              |
| ---------- | -------------------------- | --------------- |
| 主用户：学生     | 熟悉基本命令行或可借助 AI 助手运行工具；时间有限 | 少操作、看得懂进度、出错能补救 |
| 辅助角色：AI 助手 | 受学生委托在本机执行工具               | 命令清晰、错误明确、输出可解析 |
| 维护角色：开发团队  | 接手产品迭代                     | 边界清楚、模块解耦、可测试   |

### 2.2 核心场景

**场景 A：批量完成自测**
学生第一次使用，配置账号和范围后启动工具。工具在后台依次完成所有章节的自测，学生通过浏览器面板观察进度，完成后查看平均分与失败项。

**场景 B：中断后续跑**
学生中途关闭电脑或网络中断。再次启动时，工具自动跳过已完成的部分，只处理剩余任务。

**场景 C：期末复习**
学生运行题库汇聚功能，把平台历史任务中的题目导出为 HTML。期末按关键词搜索题目、展开查看正确答案与解析。

**场景 D：排查异常**
某几套题分数异常或提交失败。学生在面板中定位到具体章节和会话，查看记录与日志，决定是否重刷。

### 2.3 用户旅程

```text
获取工具 → 配置账号与范围 → 启动 → 观察面板 → 处理异常 → 查看成绩 → 导出题库 → 复习
```

## 3. 范围界定

### 3.1 首版包含

- 账号配置与本地保存（含无回显输入）
- 课程目录解析与任务计划生成
- 自动组卷、自动作答、自动交卷、成绩回收
- 进度、成绩、异常的可视化
- 断点续跑与强制重跑
- 题库汇聚、去重、多格式导出
- 本地日志与 CSV 导出

### 3.2 首版不包含

- 多用户、多账号切换
- 云端同步与跨设备恢复
- 图形化安装器与自动更新
- 自定义答题模型接入（预留扩展点即可）
- 平台接口变更的自动适配
- 移动端适配（面板以桌面浏览器为主）

## 4. 功能需求

### FR-1 账户与配置

**FR-1.1 首次配置**
提供交互式配置流程，引导用户填写平台地址、账号、密码、要处理的章节范围与运行参数。
验收标准：
- 账号与密码输入时不显示在终端。
- 配置保存在本地，默认不进入版本控制。
- 仓库中提供的配置文件模板不含任何真实凭据。
- 支持通过环境变量覆盖关键配置。

**FR-1.2 配置校验**
启动任务前校验必填项与取值范围。
验收标准：
- 缺少账号或密码时给出明确提示并停止，不进入任务流程。
- 章节范围非法时提示具体错误。
- 配置文件损坏时给出可理解的错误，不输出堆栈给用户。

### FR-2 任务规划

**FR-2.1 课程目录发现**
工具应能从平台课程页面识别出可选章节及其下属文件，形成任务清单。
验收标准：
- 清单覆盖用户选定章节下的全部目标文件。
- 清晰展示每个任务的章节、文件名与唯一标识。
- 目录解析失败时提示"平台页面结构可能变化"，而不是静默产出空清单。

**FR-2.2 范围筛选**
用户可指定章节、限定任务数量、强制重跑。
验收标准：
- 章节参数能正确筛选章节。
- 数量限制按筛选后的顺序生效。
- 强制重跑时忽略本地完成记录。

### FR-3 自动作答执行引擎

**FR-3.1 单任务执行**
对每个任务依次执行：发起组卷 → 获取题目 → 逐题作答 → 提交 → 等待评阅 → 记录结果。
验收标准：
- 题目类型被正确区分（单选/多选）。
- 提交的答案格式与平台要求一致，能被平台正常评阅。
- 单任务失败不影响后续任务。
- 每个任务产生唯一会话标识，可用于回查。

**FR-3.2 作答来源**
作答能力优先复用平台自带的问答能力；该能力不可用时，应允许后续替换为其他实现。
验收标准：
- 作答逻辑与平台 HTTP 逻辑分离，便于替换。
- 作答结果可被解析为明确选项；无法解析时记为失败而非猜测。
- 作答过程保留原始返回，便于复盘。

**FR-3.3 节流与重试**
工具应对平台限流和临时故障具备韧性。
验收标准：
- 遇到限流或服务端错误时自动重试，次数与间隔可配置。
- 重试耗尽后记录失败原因并继续下一个任务。
- 不在短时间内并发请求同一平台接口。

### FR-4 执行监控与恢复

**FR-4.1 进度记录**
每个任务的状态变化都要持久化。
验收标准：
- 状态包括：待执行、执行中、成功、失败、已跳过。
- 成功记录包含得分与会话标识。
- 失败记录包含错误类型与摘要。
- 记录可在程序重启后读取。

**FR-4.2 断点续跑**
再次启动时默认跳过已成功任务。
验收标准：
- 已完成任务不重复发起组卷。
- 失败任务可被重新执行。
- 用户可手动清除记录以强制重跑。

**FR-4.3 日志**
控制台与面板都能看到运行日志。
验收标准：
- 日志写入本地文件，面板可读取尾部内容。
- 日志不输出账号、密码或完整请求凭据。
- 日志按时间顺序追加，不被覆盖。

### FR-5 题库汇聚与复习

**FR-5.1 题目采集**
从平台可访问的历史任务数据中采集题目、选项、正确答案与解析。
验收标准：
- 采集范围覆盖用户账号下可见的相关任务。
- 题目按题干去重。
- 同题多来源时合并来源信息，不丢失解析。

**FR-5.2 多格式导出**
导出 HTML、Markdown、JSON 三种格式。
验收标准：
- HTML 支持关键词筛选与展开查看答案解析。
- Markdown 适合打印或导入笔记软件。
- JSON 保留完整结构化字段，便于二次开发。
- 导出文件不包含账号密码。

**FR-5.3 图片题处理**
部分题目可能包含图片。
验收标准：
- HTML 中图片正常显示。
- Markdown 中图片题被明确标记，避免信息丢失。

### FR-6 可视化控制台

**FR-6.1 总览**
展示整体进度与关键指标。
验收标准：
- 包含：任务总数、已完成数、平均分、满分数量、失败数量。
- 展示总体完成率与各章完成率。
- 展示每个已出分任务的得分。
- 展示运行日志尾部。
- 数据刷新延迟不超过 10 秒。

**FR-6.2 记录页**
展示每个任务的详细记录。
验收标准：
- 支持按文件名、章节、备注搜索。
- 支持状态筛选。
- 支持导出 CSV。
- 失败项显示可读的错误摘要。

**FR-6.3 题库页**
展示汇聚后的题目。
验收标准：
- 支持关键词搜索。
- 支持题型筛选。
- 点击题目展开答案与解析。
- 正确选项有明确视觉标识。

**FR-6.4 启动体验**
控制台应在任务执行期间保持可用。
验收标准：
- 用户启动主流程后，能立即打开面板观察进度。
- 面板展示完整任务计划（含尚未开始的任务），而不只是已有记录的任务。
- 面板关闭后后台任务不中断。

### FR-7 安全与隐私

**FR-7.1 凭据处理**
验收标准：
- 密码不回显、不明文写日志、不进入导出文件。
- 配置文件被版本控制忽略。
- 文档中不包含任何真实账号或密码示例。

**FR-7.2 本地边界**
验收标准：
- 面板服务仅监听本机回环地址。
- 所有数据默认保存在本地，不主动上传第三方服务。

## 5. 信息架构与交互规范

### 5.1 视图结构

```text
控制台
├── 总览
│   ├── 关键指标区
│   ├── 进度区（总体 + 各章）
│   ├── 得分区
│   └── 日志区
├── 刷题记录
│   ├── 筛选区
│   ├── 记录表
│   └── 导出入口
└── 复习题库
    ├── 搜索与筛选区
    └── 题目列表（可展开）
```

### 5.2 状态反馈

| 状态  | 视觉建议       | 文案示例 |
| --- | ---------- | ---- |
| 待执行 | 中性灰        | 待刷   |
| 执行中 | 品牌色 + 动态指示 | 进行中  |
| 成功  | 绿色         | 完成   |
| 失败  | 红色         | 失败   |
| 已跳过 | 浅灰         | 已跳过  |

### 5.3 视觉原则

- 信息密度优先，装饰从简。
- 使用清晰的字体层级、留白与细线划分区域。
- 颜色只用于表达状态，不用于大面积背景。
- 表格与代码块必须可打印、可复制。

## 6. 数据需求

### 6.1 核心实体

| 实体   | 关键字段                    | 说明          |
| ---- | ----------------------- | ----------- |
| 配置   | 平台地址、账号引用、章节范围、运行参数     | 账号密码以安全方式存储 |
| 任务   | 章节编号、文件名、唯一标识           | 由课程目录推导     |
| 执行记录 | 任务标识、状态、会话标识、得分、错误摘要、时间 | 支持续跑与审计     |
| 题目   | 题干、题型、选项、正确答案、解析、来源     | 题库基本单元      |
| 作答明细 | 会话标识、题目、原始作答、最终选择       | 用于复盘        |

### 6.2 数据生命周期

- 配置：用户主动修改或删除。
- 执行记录：长期保留，支持手动清理。
- 作答明细：随执行记录保留，可按需清理。
- 题库导出：用户自行管理生成文件。
- 日志：滚动保留，避免无限增长。

## 7. 平台集成要求

### 7.1 外部依赖

产品依赖课程平台提供以下能力：
1. 账号认证
2. 课程目录与章节文件浏览
3. 自测组卷、交卷与评阅
4. 成绩查询
5. 历史任务与题目数据
6. 问答助手能力（用于自动作答）

### 7.2 集成原则

- 所有平台交互集中在独立适配层，业务逻辑不直接依赖平台页面结构。
- 平台地址、模型名称、等待时长等外部参数必须可配置。
- 接口变更时应只修改适配层，不影响任务规划与界面。
- 附录 A 记录了当前固定站点已验证的接口与页面事实，技术团队应以此为基础复核并形成接口契约文档与 mock 测试。
- 对平台的不确定性（限流、排队、页面改版）要有超时、重试与降级策略。

### 7.3 不做的事

- 不依赖平台内部未公开的数据库或文件系统。
- 不绕过平台的身份验证、权限校验或防作弊机制。
- 不缓存用户凭据到云端或第三方服务。

| 类别   | 要求                               |
| ---- | -------------------------------- |

| 可维护性 | 模块边界清晰；外部适配层独立；关键逻辑可测试           |
| 可观测性 | 日志、状态、错误摘要三处一致                   |
| 可用性  | 首次使用不需要阅读长文档即可跑通                 |

## 9. 合规与伦理

- 产品仅用于课程自测与复习，用户需遵守所在课程与平台规定。
- 不提供任何绕过监考、伪造成绩或规避平台规则的能力。
- 用户账号密码由用户自行提供并承担保管责任。
- 题库内容仅用于个人复习，不应公开分发或用于商业用途。
- 产品不应鼓励"只刷分不学习"，界面文案应体现复习导向。

## 10. 风险与缓解

| 风险        | 影响         | 缓解策略              |
| --------- | ---------- | ----------------- |
| 平台页面或接口变更 | 任务失败       | 适配层隔离；契约测试；版本化配置  |
| 平台限流严格    | 耗时增加或失败率上升 | 退避重试；可调间隔；禁止并发    |
| 问答能力不可用   | 无法自动作答     | 模型可配置；预留替换接口      |
| 账号信息泄露    | 安全与隐私风险    | 无回显输入、环境隔离、仓库忽略规则 |
| 题库含图片或公式  | 导出内容不完整    | HTML 保留原样；MD 明确标记 |
| 用户误用于正式考核 | 合规风险       | 明确使用边界；不实现监控绕过    |
| 长时间运行中断   | 进度丢失       | 状态持久化；断点续跑        |

## 12. 开放问题

1. 平台是否允许自动化访问？是否需要向课程方报备？
2. 题库内容是否允许导出与个人保存？
3. 是否需要支持多账号或班级共用？
4. 自动作答的正确率目标是多少？低于阈值是否提示用户人工复核？
5. 是否需要提供"只生成不提交"的演练模式？
6. 成绩异常时是否需要重试机制，还是仅记录供人工判断？
7. 面板是否需要多语言支持？
8. 产品最终名称与品牌标识是什么？

## 13. 术语表

| 术语       | 含义                      |
| -------- | ----------------------- |
| 章节       | 课程目录中的一级主节点             |
| 文件 / 小节点 | 章节下可被打开并发起自测的资料文件       |
| 自测       | 平台提供的 AI 辅助测验，每组卷生成若干题目 |
| 会话       | 一次自测的唯一标识，用于交卷与查分       |
| 任务计划     | 根据用户范围推导出的待执行任务全集       |
| 题库       | 从平台历史数据中汇聚、去重后的题目集合     |

## 附录 A：当前固定站点事实档案

> 本附录记录对目标站点（地址固定，见 A.1）已验证的页面结构、接口行为与数据格式。它是**集成事实**，不是产品需求；技术团队应以此为基础做兼容性设计，而不是把实现写死。

### A.1 站点基本信息

| 项目   | 事实                                           |
| ---- | -------------------------------------------- |
| 根地址  | `http://10.20.212.33:5000/`（校园内网地址，公共互联网不可达） |
| 站点名称 | AI+基因组信息学教学平台                                |
| 教师信息 | 张高川，苏州大学苏州医学院生命科学学院计算生物与生物信息学系               |
| 访问前提 | 需要先登录；未登录访问受保护路径会重定向到登录页                     |
| 用户分组 | 页面注入 `userGroup`（学生端为 `student`），用于控制功能可见性   |

### A.2 认证与会话

- 登录页路径：`/用户管理/登录`，表单字段为 `username`、`password`，提交方式为 POST。
- 登录成功后跳转学生首页，服务端下发两个关键 Cookie：`session`、`csrf_token`。
- 调用 AI 助手类接口时需要在请求头携带 `X-CSRF-Token`，值取自 `csrf_token` Cookie。
- 站点另有 `/api/key/public` 返回 RSA 公钥，用于加密用户自备模型密钥；本产品使用平台默认模型时不需要该密钥。

### A.3 课程目录结构

- 资料页 `/资料` 的 HTML 中注入全局变量 `var graphData = {...};`，描述整个课程知识树。
- 树节点常见字段：`id`、`name`、`type`、`required`、`duration`、`files`、`children`。
- 顶层节点按数字前缀命名，如 `0_预习`、`1_绪论`、`2_测序`、`3_组装`、`4_注释`、`5_数据库`、`6_实验`。
- 每个顶层章节节点自身带有 `files` 数组，元素是 `.md` 文件路径；这些文件正是学生点击进入自测的"小节点"。
- 当前站点第 1–5 章共约 26 个 `.md` 文件，具体数量以运行时解析为准。
- 文件路径在树里使用反斜杠分隔（如 `2_测序\基因组测序.md`）；构造访问 URL 时应保留该原始路径，仅对非 ASCII 字符做 URL 编码，不要擅自替换分隔符。

### A.4 章节资料页

路径模板：`/资料/render_md?md_path=...&node_name=...&node_id=...&required=1&duration=1000`

页面内可提取的关键全局变量：

| 变量                    | 含义                                                    |
| --------------------- | ----------------------------------------------------- |
| `window.kpId`         | 当前知识点 ID，用于组卷请求                                       |
| `window.mdFilePath`   | 当前文件路径（以 JS 转义字符串形式出现，含 `\u` 编码）                      |
| `window.selftestInfo` | 形如 `{"chapter":1,"current":1,"limit":99}`，记录该章自测计数与上限                 |

其他事实：
- 页面右上角有"自测 X/99"标记，点击可查看自测次数详情。
- 页面存在嵌入式 AI 按钮、隐藏图片按钮等浮动控件。
- 页面会调用 `/资料/api/sync_learning` 同步学习时长。
- 自测按钮的提示与已学习时长有关，例如"已学习 0 分钟，可开始"。

### A.5 题型与组卷配置

- 题型接口：`/资料/api/question_types`，返回 `qt01` 单选题、`qt02` 多选题、`qt03` 问答题、`qt04` 论述题。
- 当前自测配置界面只开放单选与多选；问答题、论述题设置项禁用。
- 组卷校验规则：总题数 ≥ 10，总分必须等于 100，否则"开始测试"不可用。
- 默认配置为单选 5 题、多选 5 题、每题 10 分。
- 时长可配置为分钟数，0 表示不限制。

### A.6 自测生成与作答

**生成接口**：`POST /功能/api/selftest/generate`

请求体关键字段：

```json
{
  "node_id": "章节节点ID",
  "md_path": "资料文件路径",
  "config": [
    {"qtype_id": "qt01", "count": 5, "score": 10},
    {"qtype_id": "qt02", "count": 5, "score": 10}
  ],
  "duration": 0
}
```

响应关键字段：

| 字段                                                         | 说明                      |
| ---------------------------------------------------------- | ----------------------- |
| `success`                                                  | 是否成功                    |
| `session_id`                                               | 本次自测会话 ID               |
| `redirect`                                                 | 答题页地址                   |
| `md_name` / `node_id` / `task_name` / `duration` / `rules` | 交卷时需要原样回传               |
| `questions`                                                | 以 `qt01`、`qt02` 为键的题目分组 |

题目对象结构：`{"id": "...", "content": "...", "options": ["...", "..."]}`。
题目 ID 形如 `<session_id>_AI_qt01_1`。
**重要：生成响应不包含正确答案。**

生成耗时经验值：约 30–90 秒，受服务端负载影响。

**答题页**：`/功能/api/selftest/take/<session_id>`
页面注入 `window.selftestSessionId`，题目数据从浏览器 `localStorage` 读取；前端脚本位于 `/static/js/功能/学生/学习任务提交_AI辅助自测.js`。

### A.7 交卷与成绩

**提交接口**：`POST /功能/api/selftest/submit/<session_id>`

请求体：

```json
{
  "task_data": "<序列化后的答题数据 JSON 字符串>",
  "switch_count": 0,
  "md_name": "...",
  "node_id": "...",
  "duration": 0,
  "rules": []
}
```

`task_data` 结构：以题型为键，每个题型包含 `count`、`answer_count`、`qtype_name`、`score` 和 `questions` 数组。
每道题的提交结构：`{"id": "...", "selected": 1, "student_answer": ..., "comment_score": null}`。

- 单选题：`student_answer` 是选项文本字符串。
- 多选题：`student_answer` 是选项文本数组。

**结果页**：`/功能/学生/学习任务/查看/<session_id>`

- 页面含"最终得分：X 分"或"已评阅：X 分"字样，可用于提取分数。
- 页面还注入 `window.examData`，其中每题带有 `correct_answer`、`analysis`、`comment_score`、`student_answer` 等字段，是题库采集的重要来源。
- 评阅耗时经验值：约 10–90 秒。

### A.8 AI 助手能力

| 用途   | 路径                          | 说明          |
| ---- | --------------------------- | ----------- |
| 模型列表 | `/api/models`               | 返回可用模型及默认标记 |
| 默认模型 | `/api/user/default_model`   | 当前默认模型名     |
| 公钥   | `/api/key/public`           | RSA 公钥      |
| 主题列表 | `/api/conversations/themes` | 对话主题        |
| 对话   | `POST /api/chat`            | 问答主接口       |

`/api/chat` 请求体关键字段：`model`、`message`、`session_id`、`stream`、`rag_mode`、`api_key`、`theme`、`multi_turn`、`web_search`、`inject_knowledge_frame`、`embedded_auto`。

- 使用平台默认模型时 `api_key` 可为空。
- 需要 `X-CSRF-Token` 请求头。
- 响应形如 `{"response": "D", "context_info": {...}}`。
- 页面脚本中 `inject_knowledge_frame: true`，表示会注入课程知识框架。

当前可用模型名包括 `deepseek-v4-flash`（默认）、`qwen3.6-flash`、`qwen3.7-plus`、`kimi-k2.7-code-highspeed`、`MiniMax-M3`、`deepseek-v4-pro`、`qwen3.7-max`、`kimi-k2.7-code`、`kimi-k2.6`。模型清单以运行时接口返回为准。

### A.9 任务列表与历史数据

**任务列表接口**：`/功能/学生/学习任务/数据?page=N&search=&task_type_id=`
返回字段：`tasks`、`total`、`total_pages`。每个任务常见字段：

| 字段                                 | 说明                                      |
| ---------------------------------- | --------------------------------------- |
| `id`                               | 任务 ID                                   |
| `name`                             | 任务名称                                    |
| `content`                          | JSON 字符串，含 `chapter`、`topics`、`rules` 等 |
| `conclusion`                       | AI 评阅总结，JSON 字符串，含题目统计与解析               |
| `task_data`                        | 提交数据                                    |
| `submission_id`                    | 提交记录 ID                                 |
| `status` / `is_reviewed` / `score` | 状态与得分                                   |
| `can_view`                         | 是否可查看                                   |

任务详情路径模板：`/功能/学生/学习任务/查看/<id>`、`/详细信息/<id>`、`/提交/<id>`。

`conclusion` 的典型结构：`title`、`overview`、`qtype_summary`、`low_rate_questions`、`teaching_suggestions`、`student_analysis`、`study_suggestions`。

其中 `low_rate_questions` 每题包含：`question_id`、`qtype_name`、`rate`、`avg_score`、`reason`、`content`、`options`（元素形如 `{"option": "...", "flag": 0 | 1}`）、`correct_answer`、`answer_text`。

### A.10 题库来源与去重

已验证的题库来源类型：
- 学情测试
- 过程考核
- AI 课堂测验
- AI 辅助自测
- 课堂提问
- 自主学习的 AI 辅助评阅总结

采集策略：
- 从任务列表的 `conclusion` 中提取低得分率题目及其正确答案。
- 从可查看任务的结果页 `window.examData` 中提取完整题目、答案与解析。
- 以题干文本的 MD5 作为去重键；同题多来源时合并来源与解析。

### A.11 行为约束与异常

- 平台存在"考试期间禁止切屏"提示，并通过 `visibilitychange` 统计切屏次数；该计数由浏览器 `localStorage` 维护。直接通过接口提交时，`switch_count` 传 0。
- 平台会对高频请求返回 `429 Too Many Requests`；需要退避重试，避免并发轰炸。
- 章节页的自测计数按主章节节点维护，不按单个文件维护；因此"是否刷过"不应完全依赖站点的 `selftestInfo.current`，应以本地持久化的执行记录为准。
- 未登录访问受保护接口会重定向到登录页或返回 401/{"error":"请先登录"}。
- 部分静态资源路径带 URL 编码的中文目录名，属于正常现象。
- 站点为内网服务，外部环境无法访问；任何部署形态都要求运行机器处于同一网络或已接入 VPN。
