# 站点事实核验记录（2026-11-21 只读调研）

> 说明：本记录由主理人在评审前对目标站点做**只读**核验得到，用于校正 PRD 附录 A 中"以运行时解析为准"的部分。
> 不含任何账号、密码、Cookie 或完整会话凭据。登录仅用于访问受保护的课程页面。

## 核验方式与边界

- 方式：HTTP 客户端（curl）只读 GET 请求 + 登录（POST 表单）。
- 边界：**未**调用组卷 `/selftest/generate`、交卷 `/submit`、`/api/chat` 等会产生副作用或消耗平台资源的接口。
- 登录结果：成功，学生面板显示"欢迎学生 徐儒杰"，账号有效。

## 核验结论

### 1. 登录与会话（与附录 A.2 一致）

- 登录路径 `POST /用户管理/登录`，字段 `username` / `password`，表单 `method="post"`（无 action，提交到当前路径）。
- 未登录访问受保护路径返回 302 到登录页。
- 登录成功 302 跳转 `/用户管理/我` → 再 302 到 `/用户管理/学生`（学生面板，HTTP 200）。
- 下发 Cookie：`csrf_token`（约 43 字符，Max-Age=604800）、`session`（HttpOnly）。与 A.2 一致。
- 调用 AI 类接口需 `X-CSRF-Token` 头，取自 `csrf_token` Cookie。

### 2. 资料页 URL 重定向（需补充 A.3）

- `GET /资料` → **308** 永久重定向到 `/资料/`（末尾斜杠）。
- 客户端实现应直接请求 `/资料/`，或跟随重定向（建议前者，减少一次往返）。
- 登录后面板首页实际路径为 `/用户管理/学生`（不是 `/用户管理/我`，后者是跳转中转）。

### 3. graphData 真实结构（需修正 A.3）

```js
var graphData = {
  "course": "genomics",
  "tree": { /* 顶层节点数组在此对象内 */ }
};
```

- `data.tree` 是对象，顶层节点在其子节点数组字段中（如 `children` / `nodes`，需实现时兼容）。
- 顶层节点数：8（0_预习、自主学习、1_绪论、2_测序、3_组装、4_注释、5_数据库、6_实验、9_复习等分布在各层）。
- 节点 ID 形如 `20260907180845_0001`（时间戳_序号），**子文件夹节点也有独立 id**（如"人类基因组计划" id=`20260907180845_0045`）。
- `files` 字段是**相对路径数组**，使用反斜杠 `\`，含中文目录名，如 `2_测序\基因组测序.md`、`3_组装\从头组装算法与工具\1980-NAR-....md`。构造 URL 时保留原始分隔符，仅编码非 ASCII 字符（与 A.3 一致）。

### 4. 章节文件规模（需修正 A.3 的估计）

- 实测：整棵知识树共 **796 个 .md 文件**，远大于 PRD 估计的"第1–5章约 26 个"。
- `files` 分布在**各层节点**，不只顶层章节节点。任务规划必须递归遍历整棵树；范围筛选（章节参数）必须基于文件路径前缀或节点归属，不能只看顶层节点的 files。
- 影响：任务计划数量可能很大，"限定任务数量"参数（FR-2.2）变得很重要；批量执行的时长与限流风险显著上升。

### 5. 题型与模型接口（与 A.5 / A.8 一致）

- `GET /资料/api/question_types` → `[{id:"qt01",name:"单选题"},{id:"qt02",name:"多选题"},{id:"qt03",name:"问答题"},{id:"qt04",name:"论述题"}]`。
- `GET /api/models` → 列表含 `name`、`is_default`、`base_url`、`type`；默认 `deepseek-v4-flash`。
- `GET /api/user/default_model` → `{name:"deepseek-v4-flash",...}`。

### 6. 任务列表接口（与 A.9 一致）

- `GET /功能/学生/学习任务/数据?page=1&search=&task_type_id=` → `{page, tasks:[...], total, total_pages}`。
- 任务含 `can_view`、`conclusion`（JSON 字符串，含 `qtype_summary`、`low_rate_questions` 等）、`content`、`score`、`is_reviewed` 等字段。
- `conclusion` 中确有 `low_rate_questions`，是题库采集的重要来源（与 A.10 一致）。

## 给架构/实现的提示

1. 目录解析必须递归遍历 `tree`，且兼容 `tree` 为对象/数组两种形态。
2. ~~任务唯一标识建议使用 `节点id + 文件路径` 的组合~~ **【已被 §7 推翻】**：自测按大章节点维护，任务单元应为大章节点，不应按小文件拆分。
3. 章节筛选应基于文件路径的顶层前缀（如 `2_测序\`）或节点归属，并提供按章节编号的白名单配置。
4. ~~796 个文件意味着必须支持"限量执行"~~ **【已被 §7 修正】**：真正需要限量的是"每个大章刷 N 次"的总次数，而非 796 个小文件。
5. 所有外部参数（站点地址、章节范围、模型名、等待时长、重试次数）必须可配置，不写死。

## 7. 补充核验（2026-11-21 晚）：自测题目与计数按「大章节点」维护，非按小文件

> **重要认知纠正**：用户实测发现同一大章下点进任意小章节，题目是同步的、不需要逐个文件刷；只需对大章设定"刷 N 次"。本节为只读实测确认，推翻上文 §4 / 提示 2、4 的"796 任务"假设。

### 7.1 实测方法
登录（凭据仅内存使用、不落盘 / 不写日志），对资料子页 `GET /资料/render_md?md_path=...&node_name=...&node_id=...&required=1&duration=1000` 做只读 GET，提取页面注入的 `window.selftestInfo` 与 `window.kpId`。**未**调用组卷/交卷/问答等有副作用接口。

### 7.2 关键实测数据

**(a) 传大章节点 id 时，同一大章下不同小文件返回完全相同的值：**

| md_path（2_测序 大章下） | node_id 传入 | kpId | selftestInfo |
| ---- | ---- | ---- | ---- |
| `2_测序\基因组测序.md` | `20260907180845_0005`（大章节点） | `20260907180845_0005` | `{chapter:8, current:8, limit:99}` |
| `2_测序\基因组测序模拟.md` | 同上 | 同上 | `{chapter:8, current:8, limit:99}` |
| `2_测序\SRAToolkit安装\setup-apt.md` | 同上 | 同上 | `{chapter:8, current:8, limit:99}` |
| `2_测序\测序模拟\2003-A_Simulation_....md` | 同上 | 同上 | `{chapter:8, current:8, limit:99}` |

**(b) 传各小文件自己的节点 id 时，current 各自独立（说明计数键 = node_id）：**

| md_path | node_id 传入 | selftestInfo |
| ---- | ---- | ---- |
| `2_测序\基因组测序.md` | `20260907180845_0005`（大章） | `{chapter:8, current:8}` |
| `2_测序\基因组测序\2008-Cell-....md` | `20260908122816_0053`（子文件夹） | `{chapter:8, current:0}` |
| `2_测序\测序模拟\2003-A_....md` | `20260907180845_0006`（子文件夹） | `{chapter:8, current:0}` |

**(c) 不同大章的 current 相互独立：** `2_测序`=8、`3_组装`=11、`4_注释`=6、`5_数据库`=0、`1_绪论`=5。即每个大章节点各自维护一个自测计数。

### 7.3 结论与对产品的修正

1. **自测的题目/计数是以「节点 id」为键维护的**。要对某个大章反复刷题，正确的做法是：固定使用该**大章节点的 id**（如 `2_测序` → `20260907180845_0005`）作为 `node_id` 反复发起组卷；`md_path` 可用该大章下任一文件（或大章代表文件），不影响题目归属。
2. **任务模型从"796 个小文件"改为"N 个大章节点 × 每章刷 M 次"**。原来的"逐文件遍历 + 唯一键=节点id+文件路径"属于过度拆分，会导致同一大章被重复刷、计数错乱。
3. **限量参数的语义改变**：FR-2.2 的 limit 从"任务文件数"改为"本次要刷的大章数"；新增每章重复次数参数（如 `repeat_per_chapter`）。
4. **断点续跑唯一键改变**：从 `节点id::文件路径` 改为 `大章节点id::第几次`（如 `20260907180845_0005::3`）。
5. **796 文件的问题消解**：不再需要递归遍历全树收集文件作为任务；只需识别大章节点列表（顶层或用户选定层级），任务数量从 796 降到约 9~38 个大章节点 × 重复次数。
6. 说明：`graphData` 中"顶层节点"与"带 files 的子文件夹节点"都可能是自测单元；实现时应把**用户可选的自测单元定义为"节点"而非"文件"**，默认取顶层大章节点，并允许配置层级深度。
